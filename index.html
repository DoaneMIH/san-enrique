Section 01

What Is This System?

A web-based tourism directory for the municipality of San Enrique, Iloilo. It lets local government staff manage tourist spots, events, and categories through an admin panel, while tourists browse, search, and review places on a public website with a live map.

🗺️
Interactive Map
All listings plotted on Google Maps with colored category markers and filtering.
📋
Tourist Listings
Detailed pages per place: photos, videos, contact info, GPS coordinates, reviews.
📅
Events Calendar
Upcoming fiestas, tours, and local events with dates and locations.
⭐
Reviews & Ratings
Tourists submit star ratings and comments; admins moderate them.
🔒
Admin Panel
Password-protected backend for LGU staff to manage all content.
📱
Mobile Responsive
Bootstrap 5 grid adapts to phone and tablet screens automatically.
Who uses this? Two types of users: Tourists — who browse listings, search, view the map, and leave reviews; and LGU Staff (Admins) — who log in to the admin panel to add/edit listings, manage categories, events, messages, and reviews.
Section 02

System Architecture

The system uses a classic three-tier web architecture: a browser (client), a PHP web server (XAMPP/Apache), and a MySQL database. Everything runs locally on one machine.

🌐 Layer 1 — Client (Browser)
Tourist's browser Admin's browser Google Maps JS Bootstrap 5 CSS/JS jQuery / AJAX
↕ HTTP Requests sent up, HTML/JSON responses sent back down
⚙️ Layer 2 — Server (PHP / Apache on XAMPP)
index.php (homepage) explore.php (search) listing.php (detail page) map.php (map view) admin/ (backend) api/ (JSON endpoints) includes/ (shared logic)
↕ SQL queries sent down, result rows returned up
🗄️ Layer 3 — Database (MySQL)
listings categories events admins reviews messages
🔌 External Services
Google Maps API (map + markers) YouTube / Vimeo (video embeds) Google Drive (image hosting, optional)
Key insight: PHP runs on the server. When a user opens a page, Apache calls the PHP file. PHP queries MySQL, builds the HTML, and sends it to the browser. The browser never sees PHP code — only the finished HTML.

How tables connect: A listing belongs to one category (listings.category_id → categories.id). A review belongs to one listing (reviews.listing_id → listings.id). This is called a foreign key relationship — MySQL enforces that you can't add a review for a listing that doesn't exist.

What is a "slug"?

A slug is a URL-friendly version of a name. Example: listing name "Bugtong Bato Falls" becomes slug "bugtong-bato-falls". The URL looks like listing.php?slug=bugtong-bato-falls — clean and readable.

The gallery field

The gallery column in listings stores a JSON array of file paths, like: ["uploads/listings/photo1.jpg","uploads/listings/photo2.jpg"]. PHP decodes this with json_decode() and loops through the images to display them.

Section 05

How a Page Actually Works

When a tourist visits a listing page — say Bugtong Bato Falls — here is exactly what happens, step by step, from URL to screen.

🌐
Browser Request
Tourist opens listing.php?slug=bugtong-bato-falls
⚙️
PHP Loads
Apache hands the request to PHP. PHP loads functions.php
🗄️
SQL Query
PHP calls getListing($slug) → MySQL returns the row
🔧
Build HTML
PHP fills the HTML template with data from the database
📄
Browser Renders
Finished HTML + Google Maps JS displays the page
PHP — listing.php (simplified)
// 1. Load shared logic require_once 'includes/functions.php'; // 2. Get URL parameter $slug = sanitize($_GET['slug']); // 3. Query the database $listing = getListing($slug); // 4. If not found, redirect if (!$listing) { header('Location: explore.php'); exit; } // 5. Get reviews for this listing $reviews = getReviews($listing['id']);
PHP — functions.php: getListing()
function getListing($slug) { $db = getDB(); $slug = $db->real_escape_string($slug); $result = $db->query( "SELECT l.*, c.name as category_name, c.icon, c.color FROM listings l JOIN categories c ON l.category_id = c.id WHERE l.slug = '$slug' AND l.status = 'active' LIMIT 1" ); // Also increment the view counter $db->query("UPDATE listings SET views = views + 1 WHERE slug = '$slug'"); return $result->fetch_assoc(); }
JOIN explained: A JOIN in SQL connects two tables. Here, listings and categories are joined on l.category_id = c.id — so in one query, we get both the listing details and its category name/icon/color without needing two separate queries.
Section 06

Key Features — How They Work

Here's a plain-English explanation of the most important features and the technology behind each one.

🗺️ Google Maps with Colored Markers

The map page calls getAllListingsForMap() which fetches every active listing that has GPS coordinates. PHP outputs this as a JavaScript array. The JS code loops through each listing and creates a Google Maps marker with a custom color matching the listing's category.

// PHP passes data to JavaScript $listings = getAllListingsForMap(); echo "<script>const listings = " . json_encode($listings) . ";</script>"; // JS creates markers from the array listings.forEach(item => { new google.maps.Marker({ position: { lat: parseFloat(item.latitude), lng: parseFloat(item.longitude) }, map: map, title: item.name, icon: { fillColor: item.color ... } }); });
🔍 Live Search (AJAX)

When a user types in the search bar, JavaScript sends a request to api/search_listings.php without reloading the page. This is called AJAX (Asynchronous JavaScript). The PHP file queries the database and returns JSON. JS renders the results instantly.

// JS sends search request silently fetch(`api/search_listings.php?q=${query}`) .then(res => res.json()) .then(data => { data.data.forEach(item => renderCard(item)); // show results });
📸 Photo Gallery Upload

In the admin panel, when an admin uploads photos for a listing, PHP validates each file (checks it's actually an image), gives it a unique filename using uniqid(), moves it to the uploads/listings/ folder, and saves the file paths as a JSON array in the gallery column.

// PHP handles each uploaded file foreach ($_FILES['gallery']['tmp_name'] as $i => $tmp) { $ext = pathinfo($_FILES['gallery']['name'][$i], PATHINFO_EXTENSION); $filename = uniqid() . '.' . $ext; move_uploaded_file($tmp, '../uploads/listings/' . $filename); $galleryPaths[] = 'uploads/listings/' . $filename; } // Store as JSON in DB $galleryJson = json_encode($galleryPaths);
🔒 Admin Authentication (Sessions)

Passwords are never stored as plain text. PHP's password_hash() uses bcrypt to create a one-way encrypted hash. At login, password_verify() compares the typed password against the hash — even the developer can't read the original password. After login, the admin's ID is stored in a session (server-side storage tied to a cookie) so they stay logged in as they navigate pages.

// Login check in auth.php if (password_verify($password, $admin['password'])) { $_SESSION['admin_id'] = $admin['id']; $_SESSION['admin_role'] = $admin['role']; return true; } // Every admin page starts with this check requireLogin(); // redirects to login if not logged in
⭐ Review & Rating System

A tourist fills in the review form and clicks Submit. JavaScript sends the data via AJAX to api/review.php. PHP validates it, inserts it into the reviews table, then immediately recalculates the listing's average rating with a single SQL query and updates it.

// After saving the review, update average $db->query("UPDATE listings SET rating = ( SELECT AVG(rating) FROM reviews WHERE listing_id = $listing_id ) WHERE id = $listing_id");

Section 08

API Endpoints (JSON)

The api/ folder contains PHP files that return JSON data instead of HTML. These are called by JavaScript in the browser — the page doesn't reload, only the data updates.

EndpointMethodParametersReturns
api/search_listings.php GET ?q=keyword&c=category JSON array of matching listings
api/review.php POST listing_id, reviewer_name, rating, comment {"success": true}
api/contact.php POST name, email, subject, message {"success": true}
api/content.php GET type parameter JSON with listings or events data
What is JSON? JSON (JavaScript Object Notation) is a text format for data, like: {"name": "Bugtong Bato Falls", "rating": 4.5}. PHP creates it with json_encode() and JavaScript reads it with response.json(). It's the language browsers and servers use to share data without reloading the page.

includes/db.php — Database Connection

// Database settings (change these on deployment) define('DB_HOST', 'localhost'); // MySQL is on the same machine define('DB_USER', 'root'); // Default XAMPP username define('DB_PASS', ''); // Default XAMPP password (blank) define('DB_NAME', 'san_enrique_tourism'); // Database name define('GOOGLE_MAPS_API_KEY', 'Your_Api_Map_Key'); function getDB() { static $conn = null; // static = only connects once per page load if ($conn === null) { $conn = new mysqli(DB_HOST, DB_USER, DB_PASS, DB_NAME); $conn->set_charset('utf8mb4'); // supports Filipino characters } return $conn; } function sanitize($data) { $db = getDB(); // Two layers of protection: // 1. htmlspecialchars — converts < > to safe characters (prevents XSS) // 2. real_escape_string — escapes quotes in SQL (prevents SQL injection) return $db->real_escape_string(htmlspecialchars(trim($data))); }

Section 10

Setup & Installation Guide

Everything runs on XAMPP — a free local web server. Follow these steps in order to get the system running on any Windows laptop.

Download and install XAMPP
Go to apachefriends.org and download XAMPP for Windows. Install it to the default path C:\xampp\. This installs Apache (web server), MySQL (database), and PHP all at once.
Copy the project folder
Copy the san-enrique/ folder into C:\xampp\htdocs\. The full path should be C:\xampp\htdocs\san-enrique\. This is XAMPP's web root — files here are accessible at localhost/.
Start Apache and MySQL in XAMPP Control Panel
Open the XAMPP Control Panel and click Start next to both Apache and MySQL. Both should turn green. Apache serves the PHP files; MySQL runs the database.
Import the database
Open your browser and go to http://localhost/phpmyadmin. Click New on the left sidebar, create a database named san_enrique_tourism. Select it, click the Import tab, choose the database.sql file from the project folder, and click Go. This creates all 6 tables and loads the sample data.
Open the website
Visit http://localhost/san-enrique in your browser. The homepage should appear with listings, categories, and stats loaded from the database.
Login to the Admin Panel
Go to http://localhost/san-enrique/admin/login.php. The default credentials are set during database import. Username: admin — check the database.sql file for the exact default credentials or reset the password through phpMyAdmin.
(Optional) Add a Google Maps API Key
To enable the map, open includes/db.php and replace 'Your_Api_Map_Key' with a real API key from Google Cloud Console. Enable the "Maps JavaScript API". The free tier covers about 100,000 map loads per month — more than enough for any municipal site.
Presentation tip: Before every demo, export your database via phpMyAdmin → Export and save the SQL file to a USB drive. If the laptop restarts, you can re-import in under 2 minutes. XAMPP has no auto-backup.

Section 12

Likely Panel Questions & Answers

Practice these. Know them cold. Your panel will likely ask at least half of these.

Q Is the admin panel secure?
Yes, with appropriate caveats. Passwords are hashed using bcrypt via password_hash() — not stored in plain text. Sessions are used for authentication. All user inputs pass through the sanitize() function which prevents both XSS and SQL injection. What it lacks for production: CSRF tokens on forms and a login rate limiter. These are standard hardening steps, not rebuilds — small additions that would take hours to add.
Q Why localhost and not a live server?
Localhost was chosen for development speed, zero cost, and no internet dependency. The entire project can migrate to any cPanel shared hosting or VPS in under an hour — the codebase is standard PHP/MySQL with no framework dependencies. The first deployment step is changing the BASE_URL constant and database credentials in includes/functions.php.
Q What happens if the database gets full?
MySQL has no hard cap — it's limited only by the hard drive. With 100 listings, 10 photos each at 5 MB max, the worst case is about 5 GB — manageable on any modern laptop. For a live deployment, images would move to Cloudinary (25 GB free) and only their URLs stored in MySQL, keeping the database tiny regardless of how many photos are uploaded.
Q Can this handle many users at once?
On XAMPP for demo purposes, Apache handles about 50 concurrent connections. For a real deployment on a VPS using Nginx + PHP-FPM, it scales to thousands. The codebase is stateless (no shared in-memory state between requests), so horizontal scaling — adding more servers — is straightforward when the time comes.
Q What if the Google Maps API key hits its limit?
Google gives $200 free credit monthly — enough for roughly 100,000 map loads. For a municipal tourism site with realistic traffic, this is effectively free forever. If it exceeds limits, the map shows a "for development only" watermark but remains functional. Before going live, the key should be restricted to specific domains via the Google Cloud Console.
Q What does the sanitize() function actually protect against?
Two threats. First, SQL injection — where an attacker types SQL code into a form field to manipulate the database. real_escape_string() escapes quotes so the database treats the input as literal text, not SQL commands. Second, XSS (Cross-Site Scripting) — where malicious JavaScript is injected into a page. htmlspecialchars() converts < and > to safe display characters so scripts never execute.
Q What's the difference between a session and a cookie?
A cookie is stored in the browser. A session is stored on the server. When an admin logs in, PHP creates a session on the server and sends the browser only a random session ID (in a cookie). On every page load, PHP looks up that ID and retrieves the stored data (admin ID, role, name). This is more secure than cookies because the actual data never leaves the server.
Q How would you add a new feature to this system?
The modular structure makes this straightforward. To add a new feature — for example, a QR code generator per listing — you would: (1) add a new function to functions.php, (2) add the UI in listing.php or a new page, (3) add a database column if needed. The architecture is intentionally simple and extensible. Google Maps, video support, and reviews were each added this way.
Bottom line for your panel: This is a fully functional, deployment-ready municipal tourism platform. Its localhost nature is a development choice, not a limitation — migration to a live server is a configuration change, not a rebuild. The main gaps (security hardening, backups, hosting) are well-understood and have clear, low-cost solutions.

Glossary of Terms Used

Quick definitions of every technical term used in this system.

PHP
Server-side programming language. Runs on Apache and generates HTML before sending it to the browser.
MySQL
The database system that stores all the data in tables with rows and columns.
XAMPP
Free software bundle that installs Apache, MySQL, and PHP on your laptop for local development.
SQL
The language used to talk to MySQL. SELECT fetches data, INSERT adds rows, UPDATE changes them, DELETE removes them.
JOIN
SQL command to combine rows from two tables. Used to get listing data AND its category in one query.
Foreign Key
A column that references a row in another table. listings.category_id links to categories.id.
slug
URL-friendly version of a name. "Bugtong Bato Falls" becomes "bugtong-bato-falls".
session
Server-side storage that persists across page loads, identified by a cookie. Used to keep admins logged in.
AJAX
Technique to fetch data from the server without reloading the page. Used for live search and review submission.
JSON
Text format for data exchange. PHP creates it with json_encode(), JavaScript reads it with .json().
bcrypt
Algorithm used by password_hash() to encrypt passwords. One-way — cannot be reversed.
sanitize()
Custom function that applies htmlspecialchars() and real_escape_string() to prevent XSS and SQL injection.
Bootstrap 5
CSS/JS framework that provides responsive grids, buttons, cards, and mobile layout out of the box.
API
In this system, PHP files in the api/ folder that return JSON data to JavaScript instead of HTML.
CRUD
Create, Read, Update, Delete — the four basic database operations. The admin panel does all four for listings.
require_once
PHP command to include another file. Used to load functions.php at the top of every page.
